How it works

Type a keyword, pick a niche and a vibe. Handle applies TikTok's current rules (2–24 characters, letters, numbers, periods, underscores — no leading or trailing period, no consecutive periods) and runs each generated name through a live availability check on TikTok, with a timestamp.

The verdict reads "Likely available," "Likely taken," or "Unknown" — never a confident "Available" — because availability changes between check and click. If the check can't reach TikTok, you see a direct link to verify it yourself.

Why Handle

Three things the other generators skip

Most TikTok name generators stop at the list. You copy a name, open TikTok, and find out it's taken. Then you do it again. Then again. Handle closes that loop.

  • Live availability check. Each generated handle is checked against TikTok's own profile endpoint before you see it.
  • Honest verdicts. "Likely available" with a timestamp beats a confident "Available" that's wrong by the time you click.
  • Rules enforced up front. Every name follows TikTok's current character rules before it reaches you — no copying a 25-char handle just to find out TikTok won't accept it.

What this site does

Handle is a free TikTok username generator. You type a keyword, pick a niche and a vibe, and the site returns a list of handle ideas that follow TikTok's username rules. Each handle is then checked against TikTok's own profile endpoint so you can see whether it's likely available, likely taken, or unknown (the check could not be completed).

What we collect

Nothing directly identifying. The generator is client-side: the keyword, niche, vibe, and result list never leave your browser in a way that identifies you. The availability check is a server-side request to TikTok's public profile/oEmbed endpoint, initiated by your click. The checked handle is not associated with a user profile on our side.

Server logs. Like most web servers, our host records IP address, user-agent, request path, and timestamp in standard access logs, retained for 30 days for security and abuse prevention.

Cookies and local storage. The core tool sets no cookies. The site stores one value in your browser's localStorage — a flag recording that you dismissed the cookie consent banner — so the banner doesn't reappear on every visit. That value is handle.cookieConsent.v1 = "accepted". It is never sent to our server, never read by any third party, and you can clear it at any time via your browser's developer tools or by clearing site data.

Third parties

TikTok / ByteDance. The availability check makes a request to TikTok's public oEmbed endpoint and profile URL. TikTok sees the request from our server's IP, the handle being checked, and the standard HTTP headers (including our User-Agent). TikTok's own privacy policy governs what they do with that request.

Hosting and CDN. Our static site is served via a CDN; static requests route through edge nodes that log IP/UA/path for their own abuse-prevention purposes.

Advertising (planned, not yet live). If we enable Google AdSense, Google will set cookies and read identifiers to deliver and measure ads. You'll see a clear notice and consent flow before this happens. We will update this policy to list the specific Google cookies and how to opt out before the integration is enabled.

The site is not directed at children under 13 and we do not knowingly collect information from them. If you believe a child has provided information through the site, contact us so we can delete it.
